# 06_开发任务表

## 1. 文档说明

本任务表用于指导智慧书法教学软件首版开发实施，统一规范 4 类任务：

- `STU`：学生端
- `TCH`：教师端
- `API`：业务后端
- `AI`：智能评测服务

任务按优先级分成 3 层：

- `P0`：必须完成，能够支撑完整答辩闭环
- `P1`：体验增强，用于提升演示质量
- `P2`：扩展规划，作为后续迭代方向

## 2. 当前实现状态说明

结合当前仓库状态，以下内容已经至少具备首版骨架或可运行闭环能力：

- 教师端、学生端双前端工程已建立
- 前端已接入 `vue-router + pinia + axios`
- 教师端与学生端已具备高保真界面骨架
- 后端已具备首版核心业务接口
- 本地联调脚本与外网演示脚本已区分
- 运行文档、外网演示文档和答辩当天操作稿已补齐

因此，这份任务表不再只面向“从零搭建”，也面向“继续完善、补齐和答辩收口”。

### P0 完成标准

达到以下链路，即可视为首版答辩闭环成立：

教师发布任务 → 学生提交作业 → 系统评测 → 教师查看结果 → 看板展示

## 6. 与当前仓库对应的补充事项

除了功能本身，当前仓库还存在几类“实施层任务”，这些也建议纳入实际推进：

### 6.1 运行与演示

- 保持 `scripts/02_本地联调` 与 `scripts/03_外网演示` 两套脚本同步
- 保持 `docs/05_run` 中三份运行文档同步
- 答辩前至少做一次“6 个终端外网演示彩排”

### 6.2 文档维护

- 新增脚本后同步更新 `docs/05_run/05_本地运行与联调手册.md`
- 新增运行方式后同步更新 `docs/README.md`
- 不再把旧版本说明塞回主文档，统一归档到 `docs/archive`

### 6.3 前端验收

- 教师端和学生端保持统一视觉语言
- 核心页面持续做手机端和桌面端双端检查
- 需要时继续用 `playwright-smoke/` 做页面截图和冒烟检查
