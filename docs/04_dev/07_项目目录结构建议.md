# 项目目录结构建议

## 1. 当前推荐结构

```text
code/
├─ teacher-web/
├─ student-app/
├─ api-server/
├─ ai-service/
├─ docs/
├─ scripts/
│  ├─ 01_安装与修复/
│  ├─ 02_本地联调/
│  └─ 03_外网演示/
├─ playwright-smoke/
├─ zitie_downloads/
└─ README.md
```

## 2. 各目录职责

- `teacher-web/`
  教师端前端工程，负责课程班级、任务编排、教学看板、批阅复盘等页面。
- `student-app/`
  学生端前端工程，负责学习总览、任务中心、提交评测、成长档案等页面。
- `api-server/`
  业务后端工程，负责认证、课程、班级、任务、作业、评测、批阅、看板、报告等接口。
- `ai-service/`
  AI 服务工程，负责预处理、评分、问题标签、推荐练习等能力。
- `docs/`
  项目文档总目录，只放产品、设计、接口、运行、开发相关文档。
- `scripts/`
  本地安装、修复、启动、演示脚本目录，已经按用途拆成 3 组。
- `playwright-smoke/`
  本地页面验收、冒烟测试、截图检查脚本目录。
- `zitie_downloads/`
  书法字帖、素材或下载数据目录，属于项目资源，不属于核心代码。

## 3. scripts 目录现在怎么分

当前 `scripts/` 已经不是“所有脚本平铺在根目录”，而是按场景拆分：

### 3.1 安装与修复

目录：

- `scripts/01_安装与修复`

适合：

- 第一次拉起项目
- 安装前端依赖
- 修复教师端依赖异常

当前典型脚本：

- `1_安装前端依赖.cmd`
- `2_修复教师端依赖.cmd`

### 3.2 本地联调

目录：

- `scripts/02_本地联调`

适合：

- 日常开发
- 本机调试
- 同一局域网联调

当前典型脚本：

- `1_启动后端_本地版.cmd`
- `2_启动教师端_本地版.cmd`
- `3_启动学生端_本地版.cmd`

### 3.3 外网演示

目录：

- `scripts/03_外网演示`

适合：

- Cloudflare Tunnel
- 非同一局域网手机访问
- 答辩当天外网展示

当前典型脚本：

- `1_启动后端_外网版.cmd`
- `2_启动教师端_外网版.cmd`
- `3_启动学生端_外网版.cmd`

## 4. 技术栈建议

- 教师端：`Vue 3 + Vite + Pinia + Axios`
- 学生端：`Vue 3 + Vite + Pinia + Axios`
- 后端：`FastAPI + Pydantic + SQLAlchemy`
- AI 服务：`Python + FastAPI`
- 本地页面验收：`Playwright`

## 5. 目录使用原则

- 代码只放在代码目录里，不把业务代码和文档混放。
- 文档统一放在 `docs/` 中，不再散落在根目录。
- 启动脚本统一放在 `scripts/` 中，并按使用场景分组。
- 页面验收与自动化检查脚本统一放在 `playwright-smoke/`。
- 历史文档不再混入主文档，统一放到 `docs/archive/`。

## 6. 当前结构相比早期版本的改进

当前结构已经完成几项关键整理：

- 根目录不再堆放大批 `.md` 和 `.html` 文件
- 运行脚本不再全部使用英文平铺命名
- 文档已经收拢为 `docs/01_PRD` 到 `docs/05_run` 的主结构
- 本地版脚本与外网演示版脚本已经明确区分

## 7. 后续继续保持的规则

以后如果继续新增脚本或文档，建议继续遵守这几条：

- 新脚本优先放进现有的 `01_安装与修复 / 02_本地联调 / 03_外网演示` 中
- 新运行说明优先并入 `docs/05_run`
- 新页面说明优先并入 `docs/02_design`
- 新接口说明优先并入 `docs/03_api`
- 新任务拆解优先并入 `docs/04_dev/06_开发任务表.md`
