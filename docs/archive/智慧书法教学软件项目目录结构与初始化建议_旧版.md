# 智慧书法教学软件项目目录结构与技术栈初始化建议

## 1. 目标

本建议面向当前已经确定的技术路线：

- 学生端：`uni-app` 或微信小程序
- 教师端：`Vue 3`
- 业务后端：`FastAPI`
- AI 服务：`Python + FastAPI`
- 开发工具：`VS Code`

目标不是一开始搭建一个复杂的大型系统，而是先形成一个：

- 目录清晰
- 职责明确
- 方便答辩展示
- 方便后续扩展

的项目基础结构。

## 2. 推荐项目组织方式

建议使用 `单仓库多子项目` 的方式组织代码，也就是一个总目录下管理学生端、教师端、后端和 AI 服务。

推荐原因：

- 适合在 VS Code 中统一打开和维护
- 便于课程项目、小团队协作
- 答辩时容易展示完整系统结构
- 后续部署可以拆分，也可以统一管理

## 4. 各目录作用说明

### 4.1 `docs/`

用于存放项目文档，不和代码混在一起。

建议内容：

- `PRD/`
  - 需求文档、答辩版 PRD、功能清单
- `design/`
  - 页面原型、交互说明、视觉规范
- `api/`
  - 接口文档、字段定义、联调说明
- `demo-scripts/`
  - 答辩讲稿、演示流程
- `images/`
  - 页面截图、流程图、架构图

### 4.2 `student-app/`

学生端项目目录，建议放：

- uni-app 页面
- 公共组件
- 请求封装
- 状态管理
- 页面样式

### 4.3 `teacher-web/`

教师端和后台前端目录，建议放：

- Vue 3 页面
- 路由配置
- 状态管理
- UI 组件
- 数据看板页面

### 4.4 `api-server/`

业务后端目录，建议负责：

- 登录鉴权
- 用户、课程、班级、任务管理
- 作业提交与记录
- 调用 AI 服务
- 返回评分结果
- 报告导出

### 4.5 `ai-service/`

AI 服务目录，建议负责：

- 图像预处理
- 作业图片裁剪与矫正
- 单字切分
- 基础评分
- 问题标签生成
- 推荐练习生成
- 书法知识问答

### 4.6 `shared/`

放公共定义，避免多个子项目重复写。

建议内容：

- `constants/`
  - 通用常量，如角色枚举、书体枚举、状态枚举
- `mock-data/`
  - 页面联调前的模拟数据
- `schemas/`
  - 接口字段定义、示例 JSON、数据结构说明

### 4.7 `scripts/`

放辅助脚本，比如：

- 初始化数据库
- 导入字帖资源
- 批量重命名图片
- 生成测试数据

### 4.8 `data/`

放项目数据，不建议直接塞进代码目录。

推荐结构：

- `raw/`
  - 原始字帖图像、初始采集数据
- `processed/`
  - 清洗后数据、切分结果
- `samples/`
  - 用于答辩演示的小样本数据
- `uploads/`
  - 学生上传测试样例

### 4.9 `deploy/`

放部署相关配置。

建议内容：

- Docker 配置
- Nginx 配置
- 环境变量示例

### 4.10 `tests/`

放测试代码，建议至少有：

- 接口测试
- AI 评分服务测试
- 数据处理测试

## 6. 技术栈初始化建议

## 6.1 学生端

推荐：

- 框架：`uni-app`
- 语言：`JavaScript` 或 `TypeScript`
- 请求：`uni.request` 二次封装
- 状态管理：`Pinia`
- UI：项目内自定义组件为主

初始化建议：

- 先建最小项目
- 先做页面骨架
- 先用 mock 数据联调页面
- 后接真实接口

原因：

- uni-app 更适合快速出学生端演示
- 页面开发速度快
- 小程序和 App 方向都留有空间

## 6.2 教师端

推荐：

- 框架：`Vue 3`
- 构建工具：`Vite`
- 语言：`TypeScript`
- 状态管理：`Pinia`
- 路由：`Vue Router`
- UI 框架：`Element Plus`
- 图表：`ECharts`

初始化建议：

- 先搭后台布局
- 先做看板页和批阅页
- 再做课程、任务、分析页

原因：

- Vue 3 + Element Plus 非常适合做教师端管理后台
- 看板、表单、表格、筛选都比较成熟
- 适合答辩演示和快速试点

## 6.3 业务后端

推荐：

- 框架：`FastAPI`
- ORM：`SQLAlchemy`
- 数据校验：`Pydantic`
- 鉴权：`JWT`
- 数据库：`MySQL`
- 缓存：`Redis`

初始化建议：

- 先搭认证、课程、任务、作业 4 个核心模块
- 保持接口 REST 风格统一
- 先保证能联通前端，不急着一次做完所有业务

原因：

- FastAPI 文档自动生成，对联调和答辩展示都很友好
- Python 生态和 AI 服务结合方便
- 开发效率高，适合课程项目和试点项目

## 6.4 AI 服务

推荐：

- 语言：`Python`
- 服务框架：`FastAPI`
- 图像处理：`OpenCV`
- 模型框架：`PyTorch`
- 向量检索：`pgvector` 或后期再扩展 `Milvus`

初始化建议：

- 先用规则 + OpenCV 做基础评分
- 再逐步加入模型增强
- 初期不要一开始追求“神韵评分”

原因：

- 可解释性更强
- 更适合答辩时讲清楚
- 更适合在有限周期内做出稳定效果

## 7. VS Code 开发环境建议

推荐安装扩展：

- `Python`
- `Pylance`
- `ESLint`
- `Prettier`
- `Vue - Official`
- `uni-app` 相关支持插件
- `Markdown Preview Enhanced`
- `GitLens`

推荐工作方式：

- 用一个 VS Code 工作区同时打开整个总目录
- 前端、后端、AI 服务各自独立终端运行
- 文档放 `docs/`，方便边写边改

推荐建立 `.vscode/` 配置：

- `settings.json`
- `extensions.json`
- `launch.json`

可以统一团队的格式化、推荐扩展和调试习惯。

## 8. 环境变量建议

建议所有服务都配置 `.env.example`，不要把真实账号密码写入源码。

建议字段：

```text

AI_SERVICE_URL=http://127.0.0.1:9001
```

## 9. 首版初始化优先顺序

建议不要同时把所有子项目都做到很深，而是按下面顺序初始化。

### 第一步

- 建总目录
- 建 `docs/`
- 建 `student-app/`
- 建 `teacher-web/`
- 建 `api-server/`
- 建 `ai-service/`

### 第二步

- 学生端先做 4 个页面
  - 首页
  - 任务详情
  - 上传评测
  - 评测结果

- 教师端先做 3 个页面
  - 看板页
  - 任务发布页
  - 作业批阅页

### 第三步

- 后端先做 4 类接口
  - 登录
  - 课程/班级
  - 任务
  - 作业提交

### 第四步

- AI 服务先做 3 类接口
  - 图片预处理
  - 基础评分
  - 推荐练习

## 10. 最小可运行版本建议

如果目标是最短时间做出可答辩的 MVP，建议首版只要求做到：

- 教师可以发布任务
- 学生可以查看任务和范字
- 学生可以上传作业
- 系统可以返回一个基础评分结果
- 教师可以查看该结果

也就是说，先把这条链路跑通：

`教师发布任务 -> 学生完成练习 -> 上传图片 -> AI 返回评分 -> 教师查看结果`

这条链路一旦跑通，你的项目就已经具备：

- 产品演示价值
- 技术实现价值
- 答辩展示价值

## 11. 建议结论

对你现在的阶段来说，最合适的不是追求一次性做完整系统，而是：

- 用 `uni-app` 快速做学生端
- 用 `Vue 3 + Element Plus` 快速做教师端
- 用 `FastAPI` 统一业务接口
- 用独立 `Python AI 服务` 做基础评分
- 在 VS Code 中按多子项目结构协同推进

这套方式最适合：

- 大创答辩
- 校内试点
- 快速展示
- 后续继续扩展
