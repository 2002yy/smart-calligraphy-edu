# 智慧书法教学软件设计方案

## 1. 项目定位

本项目建议定位为一套面向高校书法素养提升场景的 `智慧书法教学平台`，而不是单纯的字帖查询 App。  
它的核心价值应建立在你们现有项目方向之上，即：

- 以 `书法教学` 为主线
- 以 `AI 智能评价` 为核心能力
- 以 `高校课堂 + 支教场景 + 留学生传播 + 心理关怀` 为特色场景
- 以 `移动端学习 + 教师端管理 + 数据端分析` 形成教学闭环

结合现有材料，推荐产品名称可暂定为：

- `笔智双驱`
- `墨课`
- `智书`
- `云砚书院`

如果要更贴近答辩和项目申报语境，`笔智双驱智慧书法教学平台` 最稳妥。

## 4. 产品差异化定位

建议把产品定义为：

`一个面向高校与公共教育场景的智能书法教学系统，围绕“学、练、评、教、研”五个环节，构建从内容资源到智能反馈再到教学管理的完整闭环。`

相较普通练字 App，核心差异化应体现在 5 个方面：

- `教`：服务正式教学，不只是个人兴趣学习
- `评`：给出结构化评价，而不是只有展示
- `导`：自动生成练习建议和学习路径
- `管`：支持教师、学院、支教项目管理
- `研`：沉淀教学数据，为课题、论文、申报提供依据

## 5. 目标用户

### 5.1 核心用户

- 高校学生：参加通识课、美育课、社团课程、比赛训练
- 书法教师：布置任务、查看作业、诊断共性问题
- 学院/项目负责人：统计教学成效、管理课程与活动

### 5.2 延展用户

- 中小学支教场景学生
- 少数民族地区学生
- 国际留学生
- 心理关怀与美育融合项目对象

## 6. 核心使用场景

### 场景一：高校课堂

教师发布“欧楷基本笔画训练”，学生拍照上传作业，系统自动输出：

- 笔画完整度
- 结构重心
- 间架比例
- 笔顺规范性
- 相似范字推荐

教师端可看到班级热力分布：

- 哪个字错得最多
- 哪个笔画最薄弱
- 哪些学生需要重点辅导

### 场景二：课后自主练习

学生在移动端选择“永字八法”“偏旁专项”“行书入门”等训练包，系统根据最近表现自动推荐：

- 今日练习字
- 示范字帖
- 临摹顺序
- 纠错提示

### 场景三：支教与资源下沉

面向设备条件一般、网络不稳定地区，提供轻量离线包：

- 本地字帖资源
- 基础评分模型
- 教师录播课
- 上传后补同步

### 场景四：国际传播

留学生可通过“双语引导 + 书写动画 + 文化解读”学习汉字书法，降低门槛，提升参与度。

### 场景五：书法育人

围绕“写字状态、练习坚持度、作品情绪表达”构建非医疗化关怀模块，作为校园心理关怀辅助场景，而不是医疗诊断工具。

## 8. 智能能力设计

## 8.1 基础视觉处理

这是最容易落地、最先产生价值的一层。

能力包括：

- 纸张区域检测
- 透视矫正
- 背景去噪
- 单字切分
- 二值化与骨架提取
- 轮廓对齐

技术建议：

- OpenCV 做预处理和几何矫正
- YOLO 或轻量检测模型做作业区域检测
- U-Net/SegFormer 类模型做笔画区域分割

## 8.2 书写评价模型

评价不建议一开始就追求“神韵评分”，先从可解释性最强的结构化指标切入：

- 重心是否稳定
- 横平竖直偏差
- 字面占格比例
- 左右/上下结构协调度
- 笔画长短比例
- 疏密关系
- 单字与范字相似度

建议先形成 `规则 + 模型` 的混合评分方案：

- 规则部分保证可解释
- 模型部分提升鲁棒性

输出示例：

- 综合分：84
- 主要问题：右部偏窄、横画长度不足、重心偏左
- 建议练习：再练“德、都、部”三字中的右耳刀结构

## 8.3 垂类大模型

垂类大模型不应直接负责图像打分，而应承担“解释与引导”职责：

- 用通俗语言解释评分结果
- 根据错误生成个性化练习建议
- 回答书法知识问答
- 为教师生成课后点评
- 为留学生生成中英双语讲解

知识底座建议包括：

- 书法家
- 作品
- 书体
- 笔法
- 结体
- 章法
- 教学案例

## 8.4 推荐系统

推荐逻辑建议围绕“当前水平 + 最近错误 + 学习目标”三条主线：

- 新手推荐基础笔画和独体字
- 某偏旁薄弱时推送专项包
- 对某书体感兴趣时推送相近字帖和课程

## 8.5 AR 与沉浸式观赏

AR 建议作为 `展示亮点` 和 `答辩加分项`，不要放在 MVP 的主路径里。  
适合做的方向：

- 扫描字帖后浮现笔顺动画
- 展示名帖局部放大与讲解
- 博物馆/展厅场景互动导览

## 9. 信息架构建议

建议以“任务驱动”而不是“资料目录驱动”来设计首页。

### 学生端首页结构

- 顶部：今日任务、最近成长值
- 中部：继续上次练习、推荐课程

### 教师端首页结构

- 顶部：待批阅、课程进行中、班级告警
- 中部：班级数据看板
- 下部：共性问题分析、优秀作品展示

## 10. 页面原型建议

建议首批高保真原型至少包含 8 个页面：

1. 学生端首页
2. 字帖馆检索页
3. 单字详情页
4. 笔顺演示页
5. 拍照评测结果页
6. 训练任务页
7. 教师班级看板页
8. 作业批阅页

其中最核心的页面是 `拍照评测结果页`，建议页面布局如下：

- 左侧或上方：学生作品图
- 右侧或下方：标准范字
- 中间：半透明叠加对比
- 下方：问题标签
- 底部：推荐练习与下一步任务

## 11. 技术架构建议

## 12. MVP 建议

首版不要试图一次做全，建议 `MVP 只做最能体现智能教学价值的闭环`。

### MVP 目标

让教师可以布置作业，学生可以上传书写图片，系统可以给出基础评分和练习建议。

### MVP 功能范围

- 用户登录
- 学生加入班级
- 教师发布训练任务
- 学生查看范字与笔顺
- 学生上传练习图片
- 系统完成基础评分
- 教师查看班级数据

### MVP 暂缓功能

- AR 展厅
- 印谱模块
- 古汉语字典
- 复杂作品章法评价
- 生成式风格迁移大功能

## 13. 教学评价指标建议

为了让系统更像“教学工具”而不是“娱乐打分器”，建议评价维度固定为可解释指标：

- 笔顺规范
- 字形结构
- 重心平衡
- 布白疏密
- 笔画力度表现
- 临摹相似度
- 完成度
- 稳定度

教师还可以自定义权重，例如：

- 楷书基础课：结构 40%、笔顺 20%、重心 20%、相似度 20%
- 行书欣赏课：结构 25%、风格把握 35%、节奏感 20%、完成度 20%

## 14. 数据闭环设计

整个系统最重要的不是“识别一次”，而是形成长期成长数据。

建议形成如下闭环：

1. 学生练习并上传
2. 系统分析问题
3. 自动推荐下一轮训练
4. 教师查看班级与个体变化
5. 系统持续积累不同群体的书写特征数据
6. 为后续模型优化、论文研究、项目申报提供依据

这会让产品天然具备：

- 教学价值
- 科研价值
- 公益推广价值

## 16. 风险与注意事项

### 16.1 技术风险

- “神韵”很难量化，早期不要把目标定得过高
- 拍照环境复杂，评分鲁棒性要重点验证
- 不同纸张、不同笔种会影响识别效果

### 16.2 产品风险

- 如果只是做字库检索，会被现有内容平台替代
- 如果评分不可解释，教师很难真正采纳
- 如果功能过多，MVP 会失焦

### 16.3 合规风险

- 未成年人数据采集要注意授权
- 作品图片和人像信息要做脱敏
- 心理关怀功能要明确是辅助性、非医疗性质

## 18. 一句话总结

你们最适合做的，不是另一个“书法资料大全”，而是一个能够真正进入课堂、给出智能反馈、服务教师决策、沉淀科研数据的 `智慧书法教学系统`。

如果后续继续推进，我建议下一步直接做两件事：

- 先把这份方案细化成 `功能清单 + 页面原型清单`
- 再挑一个最能体现价值的闭环，做 `MVP 原型`

这样最容易在答辩、路演和试点中体现竞争力。

- 数据库：`MySQL / PostgreSQL`
- 缓存：`Redis`
- 文件存储：`MinIO / OSS / BOS`
- AI 服务：`Python + FastAPI 推理服务`

如果你的主要编码环境是 `VS Code`，建议整体方案进一步收敛为 `前后端分层 + AI 服务独立 + 原型优先验证` 的开发模式。

### 1. 技术落地建议

推荐采用如下目录划分，便于在 VS Code 中同时维护多个子项目：

- `calligraphy-student/`
  - 学生端 uni-app 项目
- `calligraphy-teacher/`
  - 教师端 Vue 3 项目
- `calligraphy-api/`
  - FastAPI 业务后端
- `calligraphy-ai/`
  - 图像处理、评分、推荐、问答服务
- `calligraphy-admin-data/`
  - 初始化脚本、字帖数据、测试样例

这样做的好处是：

- 学生端和教师端可以并行开发
- AI 服务不会和业务 API 混在一起
- 答辩时可以清楚说明系统架构
- 后续切换为局域网部署或云端部署更方便

### 2. 开发阶段建议

在当前阶段，不建议一开始就做“大而全”系统，而建议按 3 层推进：

#### 第一层：演示闭环

优先完成最核心的“看任务 - 上传作业 - 智能评分 - 教师查看结果”。

目标：

- 能跑通一条真实教学链路
- 能用于答辩演示
- 能让老师一眼看懂价值

#### 第二层：教学管理

在核心闭环跑通后，再补教师端管理能力。

目标：

- 能管理课程和班级
- 能批量看作业
- 能看学情数据

#### 第三层：AI 增强

最后再做垂类问答、推荐系统、双语模式和风格迁移等亮点功能。

目标：

- 提高创新性
- 提高差异化
- 增强项目竞争力

### 3. 功能清单优化版

下面这版功能清单更适合按照 `uni-app + Vue 3 + FastAPI + Python AI 服务` 去开发。

#### 3.1 P0 必做功能

这些功能建议作为首版开发目标，能在答辩中完整展示产品价值。

- 用户登录与身份区分
  - 学生、教师两个角色
- 班级与课程管理
  - 教师创建课程、班级，学生加入班级
- 训练任务发布
  - 设置练习字、截止时间、评分重点
- 字帖与范字浏览
  - 学生查看示范字、书体信息、练习说明
- 笔顺演示
  - 单字笔顺播放、基础步骤说明
- 拍照上传
  - 学生拍照上传书写作品
- 图像预处理
  - 裁剪、透视矫正、去噪、区域识别
- 基础评分
  - 结构、重心、相似度、完成度
- 问题标签输出
  - 如“右部偏窄”“横画过短”“重心偏左”
- 教师批阅
  - 查看作业、复核评分、填写点评
- 班级看板
  - 提交率、平均分、共性问题
- 学生成长档案
  - 历史成绩、趋势变化、作品记录

#### 3.2 P1 应增强功能

- 个性化练习推荐
- 偏旁专项训练包
- 教师点评辅助生成
- 书法知识问答
- 数据报告导出
- 优秀作品展示
- 字帖资源标签筛选
- 支教场景轻量离线包

#### 3.3 P2 展示亮点功能

- AR 字帖观赏
- 留学生双语模式
- 风格迁移字帖生成
- 集字创作工具
- 心理关怀辅助模块

### 6. 面向答辩的最小系统组合

如果你的目标是：

- 大创答辩
- 校内试点
- 快速功能展示

建议最小可交付组合为：

- 一个学生端 uni-app 项目
- 一个教师端 Vue 3 项目
- 一个 FastAPI 业务服务
- 一个 Python AI 评分服务
- 一套固定字帖样本和演示数据

答辩时可以演示：

1. 教师发布任务
2. 学生查看范字与笔顺
3. 学生上传书写图片
4. 系统输出评分结果
5. 教师查看班级数据和作业详情

这套组合最容易在有限时间内做出“像产品”的成果。
